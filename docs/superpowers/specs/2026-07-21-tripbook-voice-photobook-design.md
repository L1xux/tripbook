# Tripbook 재설계 — 목소리 여행 사진첩 (Voice Photobook)

> 이 문서는 기존 "AI 여행기 집필" 기획(`2026-07-21-tripbook-design.md`)을 대체한다.
> 근본 전환: **AI가 이야기를 지어내지 않는다. 사용자의 진짜 감정을 최소 노력으로 붙잡아 보존한다.**

## 1. 목적과 재정의

**한 줄 정의:** 사진마다 목소리로 감정을 남기면, AI가 *당신 말투 그대로* 짧은 캡션으로 정리해서 실물 포토북으로 만들어주는 앱.

**왜 바꾸나 (기존 기획의 문제):** 여행 사진은 "그때 그 감정을 간직"하려고 찍는다. 그런데 AI가 무드(판타지/코미디 등)로 여러 페이지 소설을 지어내면 원본 감정을 *덮어쓴다.* 이상하게 느껴지는 이유가 이것이다.

**해결하는 두 통증:**
1. 😶 **감정이 안 남는다** — 사진은 있는데 그때 느낌이 흐릿해짐 → 목소리로 그 순간의 진짜 감정을 보존
2. ✍️ **기록하고 싶지만 글쓰기가 귀찮다** → 말하기는 타이핑보다 훨씬 덜 귀찮음

**AI의 역할 (증폭, 창작 아님):**
- 음성 → 텍스트 전사
- "음… 어…" 군더더기만 걷어내고, 사용자가 한 말·말투 그대로 1~2문장 캡션으로 정리
- 사진 보고 감정 태그 후보 제안 (탭 한 번)

**AI가 절대 안 하는 일:** 지어내기 / 없던 이야기·감정 추가 / 문체를 소설처럼 각색. AI는 작가가 아니라 **속기사 겸 편집자**다.

## 2. 사업 모델 — 스위트북 인쇄 매출 (제일 중요)

앱에서 발생하는 모든 주문 = 스위트북 인쇄 매출. 앱은 스위트북 공장의 **새 수요 깔때기**다.

**존재 이유:** 스위트북은 이미 포토북 앱이 있다. 이 앱이 만드는 *새* 매출 = "글쓰기가 귀찮아 포토북을 끝까지 못 만들던 사람"을 결제까지 데려오는 것. 목소리 캡처가 그 마찰을 없앤다. 감정이 담긴 "완성된 책"은 라벨 없는 사진 그리드보다 훨씬 잘 팔린다.

**매출 극대화 레버 (MVP는 ④에 집중):**
1. 전환율 — 완성된 느낌 → 결제
2. 객단가 — 한 여행 → 여러 SKU (향후: 엽서·액자·캘린더 업셀)
3. 재구매 — 여행마다 새 책 (자연 반복)
4. **★ 선물 · 다인수 주문 (MVP 핵심)** — 감정 책은 태생이 선물. "함께한 사람에게도 보내기" → 동행자 수만큼 인쇄 주문(1여행 → N권). 선물은 지불의사가 높다.

**단위 경제성:** 포토북 판매가 ₩2~4만, 인쇄원가 ₩1만 안팎. 앱이 얹는 AI 비용(Whisper 전사 + Claude 캡션 + Haiku 감정분석)은 권당 ₩500~2천 수준으로 마진을 거의 안 갉는다.

**리스크 (문서화):** ① 스위트북이 이미 앱 보유 → "새 세그먼트를 연다"로 답. ② "목소리 책이 정말 더 잘 팔리나"는 미검증 가설 → 실사용 테스트로만 확인 가능.

## 3. 유저 플로우

```
1. 여행 만들기      제목 + 동행자 이름(선물 대상이 됨)
2. 순간 담기 🎙️    사진 + [녹음 10초] + 감정 탭 → 여행 중/후 아무때나 반복
3. AI 정리         음성→텍스트→말투 유지 캡션(창작 없음). "정리 중…" 진행 표시
4. 사진첩 다듬기    캡션 수정 / 순서 조정 / 미리보기
5. 주문 💳         ┌ 내 책 1권
                   ├ ★ 동행자에게 선물: 동행자별 배송지 → N권 인쇄
                   │   표지 문구 + 선물 메시지 페이지
                   └ 결제 → Sweetbook API로 N개 인쇄·배송
```

**"순간(Moment)"이 핵심 원자:** 사진 1장 + 음성 1개(→캡션) + 감정 태그. 여행 중이든 후든 담는 행동은 동일. GPS·지도·오프라인 같은 여행 트래커 기능은 MVP 범위 밖(YAGNI).

## 3.5 디자인 & 인터랙션 — 틴더식 순간 카드 (핵심)

디자인이 이 제품의 성패를 가른다. 사진첩이 아니라 "감정 카드 한 장 한 장"이 주인공이어야 한다.

**화면 구조 (3단):**
```
홈(서재)  ──▶  앨범(한 여행)  ──▶  순간 탭
책장에 앨범이     순간 카드들          글귀가 나타남
책처럼 진열       (A/B/C 뷰)          (A 슬라이드업/B 딤)
```
- **홈 = 여행 서재:** 앱을 열면 첫 화면. 앨범들이 **책장에 책처럼 진열**(선택 A안). 앨범 1개 = 여행 1개(Project). 탭하면 그 앨범이 열린다. `＋ 새 여행`으로 앨범 생성.
- MVP는 계정/로그인이 없으므로, 서재에 뜨는 앨범 목록은 이 기기(localStorage)에 기록된 프로젝트들로 구성한다.

- **순간 카드:** 화면 가득 찬 풀블리드 사진 1장 = 카드 1장. 세로 스택을 스와이프로 넘긴다(틴더 감성). 사진에 집중, UI 최소.
- **탭하면 글귀가 나타난다.** 나타나는 방식은 사용자가 고른다 (프로젝트 설정 토글, 기본 A):
  - **A. 하단 슬라이드업** — 사진 아래에서 반투명 그라디언트 위로 글귀가 올라옴. 사진을 안 가림. 기본값.
  - **B. 딤 + 중앙** — 탭하면 사진이 살짝 어두워지고 글귀가 중앙에 세리프로 크게. 감정 몰입형.
- **인쇄 포토북 레이아웃:** 캡션이 들어가는 페이지는 **항상 A 방식**(사진 하단의 작은 글귀). B는 사진을 덮으므로 인쇄에 부적합. 즉 A는 화면·인쇄 공용, B는 화면 감상 전용.
- 감정 태그는 카드에 작은 칩으로 표시하고, 감정별 색을 카드 악센트로 쓴다.
- 기존 필름 디자인을 아래 3.6의 확정 토큰으로 계승·확장한다.

## 3.6 확정 디자인 토큰 (프로토타입 design-v1로 승인됨)

레퍼런스: Retro(모던 미니멀, 화이트+코랄, 사진 주인공), Day One(프리미엄 저널+인쇄책), Memories(틴더 카드+그리드).

**색:** 종이 `#F7F4EE` · 먹 `#191610` · 타우프 `#8C8578` · 라인 `#E7E1D6` · **필름 앰버 `#E4531F`**(악센트 — 오래된 카메라 날짜 LED에서. 시그니처·주요 액션에만).

**타입:** UI는 시스템 산세리프(굵게) · **글귀(사용자의 말)는 명조 `Nanum Myeongjo`** — 화면 캡션이 이미 "인쇄된 책 페이지"처럼 보이게 하여 주문으로 자연스럽게 잇는다 · 날짜·쪽번호·카운터는 `DM Mono`.

**시그니처 — "목소리를 눈에 보이게":** 카드를 탭하면 사용자의 말이 명조로 조판되고, 그 옆에 **앰버 음성 파형**(진짜 목소리)과 **필름 날짜 스탬프**가 함께 뜬다. 필름 스탬프 + 음성 파형, 이 두 물건이 이 제품의 정체성.

**돈(스위트북)을 흐름에 자연스럽게 — 결제가 아니라 감정의 climax:**
- 앱이 이미 책처럼 생겼다(홈의 책등, 쪽번호, 명조 글귀, 펼침면 미리보기).
- 카드를 끝까지 넘기면 **마지막이 "책으로 만들기" 카드**(감정을 다 훑은 뒤의 자연스러운 다음 행동) → 책 펼침면 미리보기 → 주문.
- **선물 = 감정 모먼트:** 동행자 이름으로 "엄마도 이 여행에 있었죠 / 같은 책 한 권을 엄마에게" 토글 → 켜면 N권 가격. 하단에 `SWEETBOOK 인쇄·배송` 명시.

## 4. 아키텍처 — 재사용 / 버림 / 추가

**재사용 (기존 코드 ~절반):**
- Project / Photo 모델 (Photo에 emotion, note, sort_order, taken_at 이미 존재)
- Sweetbook `client.py` / `renderer.py` — 인쇄·주문 경로. 콘텐츠가 "사진+캡션"이라 포토북에 더 잘 맞음
- 위자드 셸(`Wizard.tsx`), 필름 디자인(`index.css`), 사진 이미지 엔드포인트(`GET /photos/{id}/image`)
- Haiku 사진 분석(`ai/analysis.py`) → **용도 변경**: 서사용 장면묘사 ❌ → 감정 태그 후보 제안

**버림 (지어내기 기계 전체):**
- `ai/writer.py`, `ai/parser.py`, `ai/validator.py`, `ai/prompts.py` (여러 페이지 소설 집필)
- `ai/regen.py` (서사 재생성)
- `routers/writing.py`, `routers/pages.py`의 서사 관련 엔드포인트
- 무드 5종(문체) 개념 → 감정 태그로 대체
- Page 테이블의 "250~400자 에세이 페이지" 역할 (아래 데이터 모델 참고)
- `events.py`/SSE — 집필 스트림이 사라지므로 제거. 캡션 정리 진행은 폴링으로 충분

**추가:**
- 음성 녹음: 프론트 `MediaRecorder` → 오디오 blob 업로드
- STT: **OpenAI Whisper API** (`OPENAI_API_KEY` 신규). Claude는 음성 전사 불가
- 캡션 정리: Claude Haiku, 충실한 편집(창작 금지) 프롬프트
- 선물 주문: 동행자별 수령인 + 다인수 인쇄 주문

## 5. 데이터 모델 변화

- **Project**: `mood` 제거. `title`, `companions` 유지. `cover_line`(표지 문구, 선택), `reveal_mode`(`slide`|`dim`, 기본 `slide` — 3.5의 A/B) 추가.
- **Photo → Moment 성격으로 확장**: 기존 필드 유지 + `audio_path`(원본 음성), `transcript`(전사 원문), `caption`(AI 정리본, 사용자가 수정 가능), `emotion`(태그). `ai_scene_description`은 감정 제안 근거로만 내부 사용.
- **Page 테이블 제거**: 한 "순간"이 곧 한 페이지. 캡션은 Photo에 붙는다. 별도 Page 불필요.
- **Recipient (신규)**: `project_id`, `name`, `address`, `phone`, `gift_message`. 주문 시 N명 → N개 인쇄 주문.

## 6. AI 파이프라인 (창작 금지가 핵심 제약)

```
[음성 blob] → Whisper 전사 → transcript
                              ↓
        Claude Haiku "충실한 편집" (아래 제약)
                              ↓
                          caption (사용자 수정 가능)

[사진]  → Haiku 감정 분석 → emotion 태그 후보 3개 제안
```

**캡션 정리 프롬프트 불변식:**
- 입력 transcript에 없는 사실·감정·인물·장소를 **추가하지 않는다**
- 말투와 1인칭 시점을 유지한다
- 군더더기(음/어/반복)만 정리, 1~2문장, 40~120자
- 은유·각색·소설체 금지

전사가 비었거나(무음) 실패하면 캡션 없이 진행 — 사진+감정 태그만으로도 책은 성립한다.

## 7. 에러 처리

- Whisper 실패/무음: `transcript=""`, 캡션 비움. 사용자가 직접 타이핑 가능(폴백)
- Haiku 캡션/감정 실패: 원문 transcript를 그대로 캡션으로 사용 (편집 없이라도 보존 우선)
- Sweetbook 주문 실패: 기존과 동일하게 사용자 언어로 매핑(502), 주문 전 상태 복구
- 다인수 주문 중 일부 실패: 성공/실패를 수령인별로 보고, 실패분만 재시도

## 8. 테스트 전략

- **유닛(LLM/STT 없이 모킹)**: 캡션 정리 프롬프트 조립, Whisper 클라이언트 요청 조립, 다인수 주문 페이로드 조립, 감정 태그 파싱
- **불변식 테스트**: 캡션 정리가 transcript에 없는 토큰을 만들어내지 않는지(모킹된 응답으로 계약 검증)
- **통합**: Sweetbook Sandbox 1벌(CI mock), Whisper mock

## 9. 필요한 API 키

- `ANTHROPIC_API_KEY` — Haiku(감정 분석 + 캡션 정리). 필수
- `OPENAI_API_KEY` — Whisper 음성 전사. 필수 (신규)
- `SWEETBOOK_API_KEY` / `SWEETBOOK_ENV` — 실물 인쇄·주문. 주문 단계에 필수

## 10. 범위 밖 (YAGNI)

- 여행 중 실시간 GPS/지도/경로 추적
- 엽서·액자·캘린더 등 멀티 SKU 업셀 (향후 레버 ②)
- 소셜 공유 피드, 계정/로그인
- 오프라인 녹음 동기화
